# Docker

> Docker 主要用來解決軟體開發執行時最常見的「環境不一致」問題。從根本解決「在 A 的電腦可以跑，但在 B 的電腦不能跑」的情況。

## Docker 的重要概念

### image: 映像檔

像是應用程式的快照樣板。用前端的語言說就是 `class`。

### container: 容器

- 樣板跑起來的實例。用前端的語言說就是 `instance`。
- 可以有多個 container 從同一個 image 啟動。

### Dockerfile

用來描述「怎麼從零建出這個環境」，像是 `package.json` + 安裝腳本的合體。

### registry: 映像檔倉庫

放 Docker image 的倉庫

## 常用指令

> prerequisite: install Docker Desktop

```sh
# 照著 Dockerfile 的指示，把程式碼和環境打包成一個 image 
docker build
# "docker build": 建置
# "-t": 幫產出的 image 命名
# ".": 建置上下文(build context)——告訴 Docker「以目前這個資料夾為範圍」 
docker build -t <image_name> .

# 查看本地已有的 Docker 映像檔（images）
docker images

# 啟動新的 container
docker run <image_name>
docker run hello-world

# 啟動新的 container，把容器內的 80 port 接到 local 的 8080
docker run -p 8080:80 nginx

# 列出目前正在運行的 container
docker ps

# 查看所有 container（包含停止的)
docker ps -a

# 查看單一 container 的詳細狀態
docker inspect <container_name_or_id>

# 停止指定的 container
docker stop <container_id>

# 登入
docker login

# 幫既有的 image 取一個新名字(別名)
docker tag <原名稱> <新名稱>
docket tag <source_image> <target_image>

# 下載 image
docker pull <image_name>

# 上傳 image 到指定 registry
docker push
```

## 情境

### Push Local Image to Remote

```sh
# step1: Login
docker login

# step2: add tag
docker tag <source_image> <username>/<repo> 

# step3: check images, 此時 docker images 就會看到新命名的 docker image
docker images

# step4: push to remote
docker push <username>/<repo>
```

## Docker Map

```text
Dockerfile ──build──> image ──tag──> 指向某 registry 的完整名稱 ──push──> Registry
                                                                            │
正式環境 / Cloud Run <──run── image <──────────────pull──────────────────────┘
```
