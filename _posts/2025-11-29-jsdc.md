## Kuro
> 關鍵不在於用什麼框架，而在於如何與 AI 協作

### AI v.s. Human

| **項目/角色** | **AI** | **人類** |
|----------|-----|-----|
| 需求分析 | 快速產生草稿 | 定義 Interface、預想 Edge Cases |
| 視覺設計與切版 | 在規範內進行切版實作 | 制定 Design Tokens 與 Aily 標準 |
| 元件實作 | 過時知識(AI 幻覺)、元件過大 | 確認最新文件內容、把問題拆小 |
| 前後端串接 | Only Happy Path | UX 細節與資安 |
| 效能與部署 | 快速完成功能 | 效能把關、優化體驗 |

> 搭配 eslint-plugin-tailwindcss 可在 Lint 階段偵測無效 class


### Prompt Engineer v.s. Context Engineer
- Prompt Engineer: 怎麼問，用詞彙調整 AI 行為
- Context Engineer: 給資訊架構，用結構化資訊引導 AI


### TDD 的復興
Human 定義 Interface -> AI 生成測試 -> Human 審核補充情境 -> AI 生成實作 -> Human 最終把關


### 結語
- 前端不死，真正結束的是舊的開發模式
- 無論AI 如何生成，按下 Deploy 的是你，負責的也是你
- AI讓我們走得更快，但方向由我們決定
